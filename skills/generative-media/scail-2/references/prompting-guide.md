# SCAIL-2 — prompting

**This file is short on purpose, and the reason it is short is the most useful thing in it: on SCAIL-2, the prompt is the weakest control surface you have.** Motion comes from the driving video. Appearance comes from the reference image. The masks decide which regions count as subject and which count as background. On a text-to-video model, a prompt controls all of that. On SCAIL-2, almost all of it is already decided before the model reads a word.

So this file does two jobs. First, it tells you what the SCAIL-2 prompt genuinely affects, so you can spend your effort where it counts. Second, it covers **the prompt that actually decides your result**. That is the *image-edit* prompt you write upstream, when you prepare the reference frame. It is short, and it is the one to get right.

Padding this file out with generic camera-and-motion vocabulary would be actively misleading. If you want that kind of guidance, see [`wan-2-2/references/prompting-guide.md`](../../wan-2-2/references/prompting-guide.md). It covers a model where that vocabulary works.

## 1. Where each part of the output actually comes from

Before you write anything, know which rail carries what. Most wasted prompting on this model happens when someone tries to steer a property the prompt does not own.

| Property of the output | Where it comes from | Can the prompt change it? |
|---|---|---|
| **Motion, timing, choreography** | The driving video, tracked frame for frame | **No.** *"SCAIL-2 tracks the movement sequences and does not invent its own"* `[community — External_Trainer_213]` |
| **fps and clip length** | The driving video | No |
| **Camera movement and framing** | The driving video | No. There is no camera vocabulary on this model |
| **Who the character is** | The reference image | Barely. Appearance arrives as pixels, not as description |
| **What is scene versus subject** | The masks | No. Be aware that a mismatched `replacement_mode` silently changes the operating mode |
| **Clothing, and what the character interacts with** | The reference image, *plus the prompt* | **Yes — this is the prompt's main job**, and the vendor says so for Replacement mode |
| **Secondary physics — cloth, hair, liquid, fire** | Generated by the model on top of tracked motion | Somewhat. Naming the material helps. Naming the motion does not |
| **Overall scene description** | Prompt, as context the model conditions on | Yes, weakly. It works as context, not as instruction |

The one-line version: **the prompt describes what the finished video contains; it does not tell the model what to do.**

## 2. The encoder and the guidance state

Two conditioning settings decide which dialect the prompt should be written in and whether negatives work at all. Both come from the Wan 2.1 foundation underneath.

**Encoder: umT5-XXL.** This is the same text encoder that [`wan-2-2`](../../wan-2-2/) uses, loaded through ComfyUI's CLIPLoader with **type `wan`**. A few things follow from that. It is a natural-language T5-class encoder, so you write sentences rather than comma-separated tags. It has no trigger-word grammar and no weighting syntax of its own, beyond whatever your ComfyUI text-encode node adds. It also handles both English and Chinese, because that is what Wan trained it against.

**Guidance state: live at 5.0, inert at 1.0.** The full-quality path runs real classifier-free guidance at **5.0**, so a negative prompt does what a negative prompt should do. The **LightX2V distilled path runs at guidance 1.0**, which switches CFG off, and switches negatives off with it. This is standard distilled-model behaviour, and it catches people every time. On the speed path, your negative prompt is not weak. It is *not being evaluated*. Phrase constraints positively instead, or move back to the 40-step path.

**Negatives are not where the leverage is, either way.** The artefacts people actually fight on this model — mushed small subjects, tracker refusals, clothing morph, a character too bright for the plate — all sit upstream or downstream of the prompt. A negative prompt cannot reach any of them.

## 3. The SCAIL-2 prompt

**The vendor's guidance:** SCAIL-2 is trained on **long, detailed prompts that describe the *resulting* video**. That means a description of what the finished clip contains, not an instruction to the model. For Replacement mode specifically, the vendor says to **describe the replacement character's clothing and what they interact with** `[official — wan-scail2 README]`. A **Gemini-backed `prompt_enhancer.py`** ships in the repo to expand a short prompt into that longer form.

**What practice looks like.** Every posted example in the community sweep is one line. Here is the entire SCAIL-2 half of a real two-stage workflow: *"the woman is being fucked by the tentacle"* `[community — ChairQueen]`. That is not laziness. The driving video and the edited reference had already fixed everything else.

**Reconcile the two.** The vendor's long-prompt guidance and the community's one-liners are both correct. The difference between them comes down to **how much of the result is not already in your inputs**:

- **Animation mode with a well-prepared reference.** The reference and the driving video carry appearance, pose, framing and motion. A sentence is enough. Reach for the enhancer when the model seems to be guessing about scene context.
- **Replacement mode.** The masked region is *removed* before the model sees it, so clothing and object interactions have no reference at all. This is where detail pays off, and this is where the vendor's advice is aimed. Name the garments, the materials, and what the hands are touching.

**A useful discipline either way: describe nouns and materials, not verbs.** Verbs are the driving video's job. "A woman in a heavy wool coat holding a ceramic mug" gives the model something to render. "A woman walks forward while lifting a mug" describes motion the model is already tracking, so it buys you nothing.

## 4. The upstream image-edit prompt — the one that matters

The prompt that decides your result is not written for SCAIL-2 at all. It is the image-to-image edit prompt you run on the driving clip's extracted frame 0 — the [one rule](../SKILL.md#the-one-rule-that-changes-everything). The procedure is in [`setup-and-workflows.md`](setup-and-workflows.md) §2. This section covers how to word it.

**Keep it blunt, and change one thing.** The flagship demonstration's complete edit prompt was *"make the man a blonde woman"* `[community — blackmixture]`. Another practitioner's was *"Convert the penis to a tentacle dildo and the duckt tape to a magical portal"* `[community — ChairQueen]`. That second prompt is two substitutions, both named as object-to-object swaps, with nothing about pose or scene.

**The mechanism behind the brevity rule.** You are asking the edit model to change *who is in the frame* while keeping the pose, scale, screen position, lens and lighting exactly as they were. Every extra descriptive clause is another invitation for the model to re-compose the frame, and a re-composed frame breaks the correspondence match the whole technique depends on. **A beautiful edit that moved the subject is a failed edit.**

| Do | Don't |
|---|---|
| *"make the man a blonde woman"* | *"a beautiful blonde woman with flowing hair standing confidently in a dramatic pose"* |
| Name substitutions as object → object | Describe the scene, the lighting, or the camera |
| One or two changes, iterating if you need more | Stack five attribute changes in one pass |
| Say the style if you are style-transferring the whole frame | Say anything about motion — this is a still |

**Style transfer is the same move at frame scale.** The documented anime-to-real path is: *"1: flux2klein9b image to image the 1st frame of your video into whatever style you want. 2: that image and your video go into the workflow. 3: generate."* The edit model does all the style work. SCAIL-2 just carries it through the clip.

**Which model to write for.** The named front ends are [`krea-2`](../../krea-2/)'s Identity Edit LoRA, Flux 2 Klein 9B, and Qwen-Image-Edit, often mixed within one project `[community — DeerWoodStudios]`. Flux 2 Klein *"understands natural language really well"* `[community — LucidFir]`, so plain instructions work — but plain still means short. Each of those models has its own prompting conventions. [`krea-2`](../../krea-2/) documents its Identity Edit dialect from the image side.

## 5. What not to put in the prompt

| Don't write | Why it does nothing |
|---|---|
| Motion and action descriptions | The driving video is tracked frame for frame. Describing the action is describing something already fixed |
| Camera moves — *dolly in*, *pan left*, *static shot* | The camera is the driving video's camera. There is no camera-control vocabulary on this model |
| A duration, an fps, or a shot length | All three are properties of your input clip |
| A detailed face description in the SCAIL-2 prompt | Identity arrives as pixels through the reference. Put the effort in §4 instead |
| Readable text you want to appear | Text turns to mush inside the replaced region — the model's clearest weakness |
| Negatives, on the LightX2V path | Guidance is 1.0 there, so they are not evaluated at all |
| Anything meant to fix lighting mismatch | When the inserted character reads too bright, you fix it in post with a SAM3 re-mask, not in the prompt |

## 6. Templates

**Animation mode, prepared reference.** One or two sentences naming the subject, their garments, and the setting:

> A woman in a charcoal wool overcoat and leather gloves, walking through a wet city street at night, neon reflections on the pavement.

**Replacement mode.** Longer, and weighted toward clothing and interactions, because the masked region gave the model nothing:

> The man wears a faded olive canvas jacket over a grey henley, dark selvedge jeans and scuffed brown boots. He is holding a heavy ceramic coffee mug in his right hand and a folded newspaper under his left arm. Warm interior light, a diner booth behind him.

**Upstream image edit, frame 0.** Blunt, one or two substitutions:

> make the man a blonde woman

> replace the guitar with a violin

**Style transfer, frame 0.** Name the destination style and nothing else:

> convert this frame to 90s cel anime

## 7. "My prompt did nothing" — triage

The most common SCAIL-2 support question is some form of *"I changed the prompt and the output is identical."* Usually that is correct behaviour, not a bug. The fix is to change a different rail. Work down this list:

| You wanted to change… | The prompt does not own it. Change instead… |
|---|---|
| How fast or how much the character moves | The driving video. Re-shoot it, re-time it, or interpolate the *input* — but note that interpolating the input makes SCAIL-2 *"quicker to 'forget' new parts of the animation"* ([`setup-and-workflows.md`](setup-and-workflows.md) §5.3) |
| Who the character is | The reference image, via the frame-0 edit (§4) |
| Where the character is in frame | The reference image's composition, or the SAM3 selection |
| Whether the background survives | The masks. Replacement mode altering backgrounds is a reported, unexplained failure — **RMBG background retention** is the workaround ([`masks-and-tracking.md`](masks-and-tracking.md) §5) |
| Which person gets replaced | `object_indices` on `SCAIL2ColoredMask`, and point-selection upstream in SAM3 |
| Whether the swap looks composited | The vendor's **Relighting LoRA**, which exists for exactly this; post-grading is the fallback |
| Anything at all, on the LightX2V path, via negatives | Nothing. Guidance is 1.0, so negatives are not evaluated |

**Two genuine prompt-side escape hatches remain.** Try them before you conclude the model cannot do the shot: **change the seed**, and **switch the sampler**. The general community fallback for a run that goes wrong is *"setting a new seed or switching the sampler usually helps"* `[community — External_Trainer_213]`. Neither is really a prompting technique, and that fact says a lot about this model.

**If the prompt genuinely does nothing in Replacement mode**, check that the masked region actually covers what you think it does. A clothing or interaction description only has an effect where the model has no reference, which means inside the mask. Outside the mask, you are describing pixels the model is just copying.

## 8. What a prompt-driven model charges for the same job

This comparison is worth seeing once, because it is the clearest measure of what SCAIL-2's conditioning shape buys you. One practitioner spent **six hours and 400+ generations** getting [`minimax-h3`](../../minimax-h3/) to do character replacement — a job SCAIL-2 does with one line and a prepared frame `[community — Darqsat]`. The prompt he arrived at is the price a prompt-driven model charges.

Here is its shape, quoted from the skill that owns it. [`minimax-h3`](../../minimax-h3/) carries the full block, and this skill deliberately does not keep a second copy:

> `retention_analysis:` … *"attribute_transfer - her pose, movement, and screen position are transferred to `<Subject 1>`"*

A whole structured section, written by hand, exists only to state the correspondence that SCAIL-2 gets for free from a SAM3 track.

His findings double as a description of what SCAIL-2 does without being asked. The `retention_analysis` block is the load-bearing one. The `detailed_description` block barely matters. Identity only holds if you *"add better and stronger anchor for model — something visually big like hair, clothing, position on screen"*. That anchor is exactly what an edited frame 0 supplies structurally, which is why SCAIL-2 needs no equivalent block.

The trade-off is real in both directions. H3 needs the prompt because it re-generates the motion. That is also why it can produce audio and does not need footage at all. SCAIL-2 needs footage because it tracks, and tracking is why its prompt can be one line. Choose based on which constraint you can meet, not on which prompt looks simpler.
