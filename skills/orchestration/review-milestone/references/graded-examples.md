# Graded examples: format

Evaluators start out lenient. Each verdict the owner overturns or confirms becomes an example in the project's graded
examples file (named in `ORCHESTRATE.md`), so later reviews match the owner's standard. Add new examples at the top and
keep about ten, dropping the oldest when a newer one teaches the same lesson.

Copy this into the project file when setting up:

```markdown
# Graded examples

Each example: the milestone and item; what the captures showed; the evaluator's verdict; the owner's verdict; why the
owner's verdict is right; the date.

## Examples

None yet.

## Standing calibration

Failures this project has already paid for. Fail an item showing any of these, even when its literal wording is met.
```
