# Proposal: where orchestrate's plan files live, and who each is for

## Problem

In Thrum (`~/Workspace/thrum`, read it with `git show origin/main:<path>`; the local checkout is 312 commits behind),
the owner can't find the plans or read them:

- Module plans are in `docs/design/modules/` (Thrum's own `Plans:` setting), mixed with per-module briefs. Other
  plan-shaped files sit in `docs/BUILD-PLAN.md`, `docs/design/CONSTRUCTION-PLAN.md`, `docs/design/decisions/*-PLAN.md`,
  `docs/evidence/i2a/SOURCE-SPACE-PLAN.md`, and ~10 untracked `tmp/*/…-PLAN.md` lead scratch files.
- No overview across modules exists.
- Status lines have grown into paragraphs of item IDs and jargon (COOKED-DRAW-PLAN `Now:`), and plan files are huge
  (ATMOSPHERE-PLAN.md: 795 lines, 10.7k words). Finished milestones stay in full.
- One file, `<MODULE>-PLAN.md`, serves the owner (status lines), builder (work list) and planner (log), and
  builders write into it every turn, so it accrues.

The skills allow all of this: the plans folder is configurable, nothing forbids plan files elsewhere, no overview
is asked for, the plan file names no reader, and there's no size limit. The one rule ("keep status lines short",
`plan-module/references/done-when.md`) has no check and was ignored.

## Readers

| Reader | Needs | Should not have to wade through |
|---|---|---|
| Owner (human) | Where things stand, what's next, what waits on them, what just landed | Item IDs, hashes, paths, builder narrative |
| Lead agent | The same across modules, plus the next command | Assembling it from every plan file |
| Planner | Brief, glossary, architecture, designs, decision history | Builder chatter mixed into decisions |
| Builder | Its one milestone: work, stop rules, interfaces, items | Finished milestones in full, other modules |
| Reviewer | Items, bar, design intent, evidence | The builder's account of itself (biases toward agreement) |
| Script | JSON | Prose |

## Proposed layout

```
ORCHESTRATE.md                 settings; first line links STATUS.md
docs/plans/
  STATUS.md                    owner + lead   generated by the script, never hand-edited
  BRIEF.md  GLOSSARY.md        everyone
  ARCHITECTURE.md              planner, lead
  <MODULE>.md                  agents         design: mechanisms, interfaces (stable)
  <MODULE>-PLAN.md             all            status lines, milestone list, current milestone's work list
  <MODULE>-LOG.md              planner, lead  dated one-line decisions, assumptions, failed reviews (append-only)
  <MODULE>-DONE.json           script, builder, reviewer
docs/evidence/<MODULE>/        reviewer       proof and review files
.orchestrate/scratch/          agents         untracked working notes; never named *-PLAN
```

- STATUS.md: regenerated by the script (a `status --write` or on every landing of plans/acceptance/review).
  Sections: Needs you (parked, attended items, owner-decides, unadopted plans) → Modules (one row: purpose,
  `2 of 5 done`, Now, Next) → Recently done (outcome + link to review). Structure from the JSON, wording from
  plan status lines.
- Owner requirement (added): the owner wants to see the project as a whole — every module, finished and still to
  come, in build order, with what each is for. STATUS.md's Modules section lists all modules from ARCHITECTURE.md
  (done, in progress, waiting, not started), not only active ones.
- Plan file: status lines written for the owner, plus a `Progress:` line; each milestone one outcome-phrased line;
  only the current milestone carries a detailed work list; done milestones collapse to one line + review link;
  ~150-line cap. History moves to the log.
- Writing rules by audience: owner-facing text (status lines, milestone names, module purposes) is plain words,
  glossary names, one sentence, outcome-phrased, no IDs/hashes/paths. Agent-facing text (design, work list, items)
  is precise and follows `prompting-agents`.
- Each role skill names its reading order. The reviewer never reads the log (new independence rule).
- Files stay flat (script globs `{plans}/{MODULE}-*`). Default plans folder `docs/modules` → `docs/plans`;
  existing `Plans:` settings keep working.
