## Starting from a clean clone
`cargo build --release`. There are no services, secrets or seed data. Tests make their fixtures in temporary
directories (`tempfile` or `target/`), so parallel worktrees don't share anything. The 5 GiB fixture for the
large-file test is generated deterministically under the worktree's own `target/bigfile/` and reused if it is already
the right size; it needs about 6 GiB of free disk.

## Targets

| Target | What it is | Run | Capture | Edge conditions |
|---|---|---|---|---|
| cli | The release binary on the dev machine (macOS; Linux is expected to behave the same) | `cargo run --release -- [-f] [-q QUERY] FILE...` | Terminal transcript with stdout, stderr and exit code; peak RSS from `/usr/bin/time -l` (macOS) or `-v` (Linux) | Bad arguments, malformed query, missing file, empty file, piped into `head`, Ctrl-C while following, file rotated or truncated while following |

## Rules
- **Exclusive resources:** big-file: the 5 GiB fixture and the timing and RSS measurements taken on it; one run at a time
- **Large captures:** the 5 GiB fixture is never committed; it is regenerated by the test. Evidence pages record its size, checksum of the first and last MiB, and the measurements.
- **Owner decides:** changing the goal or the query language's syntax beyond this design; adding a dependency that is not MIT or Apache-2.0; publishing to crates.io; pushing  *(loop)*
- **Licences and paths not to touch:** no GPL, LGPL or AGPL code or crates; never write outside this repository except ~/.cargo  *(loop)*
