# Pattern 6: the same rule said in more than one place

Scope: every file of the set except `lead/stages/4-build.md`. A prompt the script builds counts as a file, and the
saved copies in `tests/orchestration/prompts/` show what each agent really reads. A skill's task file (`planner/tasks/*.md`,
`reviewer/tasks/*.md`) is inlined into its prompt, so a rule in the task file and in the prompt's own lines is read
twice in one message.

The test I used for "where it should live": the place that (a) every reader who needs the rule actually reads, (b)
only once per session, and (c) knows the facts the rule depends on. Rules that depend on facts only the script knows
(which items need the user, which resources exist, the host, the scope, whether a handoff exists) belong in the
prompt the script builds. Judgement and reasons belong in the skill. How a command behaves belongs in its `--help`.

Line numbers are from the working tree as of this review. "Checked" says what I compared against.

Rough total that would go: **about 95 to 120 lines** across skills, reference files, prompt templates and
agent-facing strings in the script (counting wrapped Markdown lines at about 120 characters, and a prompt-string
sentence as about one line).

## 1. Planner tasks the script writes restate the task file that follows them (whole paragraphs)

The `--task` text the script writes for a planner repeats the instructions of the `tasks/<kind>.md` file that
`plan.md` inlines a few lines below it. The planner reads the same rule twice in one prompt, in two wordings.

| Rule | Copy in the script's task text | Copy in the task file |
|---|---|---|
| Diagnosis: read every review, decide why; plan at fault → change it, end `PLANNED`; plan sound → no file, `KEEP … builder/reviewer/human` | `diagnosis_task()` (agent_loop.py ~2399–2440), saved in `planner-diagnosis-task-new-findings.txt` and `-repeated-finding.txt`: "Read every review and decide why it keeps failing. If the plan is at fault, change what is at fault, write each item you change again from what it claims, and end with PLANNED. If the plan is sound, change no file and end with `KEEP …`" | `planner/tasks/diagnose.md` 11, 25–26, 37–44; "write each item again from what it claims" is also `planner/SKILL.md` 129–131 |
| Unblock, needs_dependency: if the plan already provides it, no file and `KEEP … builder: <where>`, script lifts the block | `planner-needs-dependency.txt` (the `next` the script prints for `BLOCKED needs_dependency`): "If the plan already provides it, change no file and end with `KEEP APPLE-TILE M2: builder: …`, and the script lifts the block." | `planner/tasks/unblock.md` 19–22 |
| Unblock, item can't be met: change it and `PLANNED`, else `KEEP … builder: <how>` | agent_loop.py 8206–8209: "If an item can't be met as written, change it and end with PLANNED. If every item can be met as written, change no file and end with `KEEP …`" | `planner/tasks/unblock.md` 33–36 |
| Revise: settle every Must Fix | `planner-after-design-changes.txt`: "Resolve its 2 Must Fix findings in the design and the plan." | `planner/tasks/revise.md` 3–7 |

**Fix:** the task text carries only facts the planner can't find: which milestone, the counts, which way it got here
(repeats / new findings / a planner field), the review paths and what failed in each, the builder's words and branch.
The instruction lives once, in the task file, because `plan.md` always inlines the kind's file and it holds the
reasons. Concretely, end `diagnosis_task()` after "What failed in each review: …"; end the unblock tasks after the
builder's words, handoff and branch; cut the revise task to "The design review of APPLE-TILE at <path> asked for
changes." The one thing only the revise task says, "Its Suggestions are yours to take or leave; say which you took
and why", moves into `revise.md`.

**Checked:** read `plan.md` (the kind file is inlined as `{kind}`), the saved prompts, and the code at 2399–2440 and
8200–8220. `KEEP`'s exact form the planner needs is already in `diagnose.md` 37 and `unblock.md` 21, 28, 35. The
`KEEP APPLE-TILE M2` form with the real names filled in is the one useful extra; it can stay as a bare
"`KEEP APPLE-TILE M2: …`" in the task if wanted.

Lines that go: about 6 long prompt sentences in the script (≈10 wrapped lines).
